## 修复 cortex-debug 报错 "GDB executable ... was not found"

**现象**：VS Code 启动调试时报 `arm-none-eabi-gdb.exe was not found`，
提示配置 `cortex-debug.armToolchainPath` / `cortex-debug.gdbPath`。

**根因**：本项目原先在另一个 Windows 账号 `Dawn` 的机器上开发
（原工程路径 `d:/Projects/stm32/AGV_Project`），`.vscode` 配置里全是
`C:/Users/Dawn/AppData/Local/...` 的硬编码绝对路径。换到本机账号
`Fawziya` 后就全部失效。

**本机正确路径**（已实测可运行）：
- gdb: `C:/Users/Fawziya/AppData/Local/stm32cube/bundles/gnu-gdb-for-stm32/14.3.1+st.2/bin`
- openocd: `C:/Users/Fawziya/AppData/Local/xpack-openocd/xpack-openocd-0.12.0-7/bin/openocd.exe`
- openocd scripts: 其上两级 `/openocd/scripts`
- SVD: `C:/Users/Fawziya/AppData/Local/stm32cube/packs/STMicroelectronics/stm32f4xx_dfp/1.2.0/SVD/STM32F407.svd`
- ELF: `build/Debug/STM32F407_CAN_CMD.elf`（存在）

**已改文件**（`Dawn` → `Fawziya`）：
- `.vscode/launch.json` — armToolchainPath、svdFile
- `.vscode/settings.json` — cortex-debug.openocdPath
- `.vscode/flash-retry.sh` — OPENOCD、SCRIPTS

**仍残留 Dawn 路径（未改，仅影响 Claude Code 的权限白名单，不影响功能）**：
- `.claude/settings.json`、`.claude/settings.local.json`、`.claude/settings.local.json.bak`

## 环境注意
- 环境变量 `CUBE_BUNDLE_PATH` = `C:\Users\Fawziya\AppData\Local\stm32cube\bundles`，

## 为接入 Git 做「防换机炸」改造（同日）

**动机**：项目尚未 `git init`。若不处理，上面的 Dawn 硬编码路径会原样进仓库，
换机器/换队友必然复现同一个报错。

### 1. 全部机器路径 → VS Code 变量（已实测 JSON 语法通过）
| 文件 | 原值 | 现值 |
|---|---|---|
| `.vscode/launch.json` | `C:/Users/<u>/AppData/Local/stm32cube/bundles/...` | `${env:CUBE_BUNDLE_PATH}/gnu-gdb-for-stm32/14.3.1+st.2/bin` |
| `.vscode/launch.json` | `C:/Users/<u>/AppData/Local/stm32cube/packs/...` | `${env:LOCALAPPDATA}/stm32cube/packs/...` |
| `.vscode/settings.json` | openocdPath 绝对路径 | `${env:LOCALAPPDATA}/xpack-openocd/.../bin/openocd.exe` |
| `.vscode/flash-retry.sh` | OPENOCD/SCRIPTS 写死 | 由 `${LOCALAPPDATA}` 推导，可用 `OPENOCD_ROOT` 覆盖；含存在性检查 |

**注意**：`packs/` 不在 `CUBE_BUNDLE_PATH` 下（bundle 根是 `.../stm32cube/bundles`），
所以 SVD 必须用 `${env:LOCALAPPDATA}`，别混用。

### 2. 顺手修掉一个死配置
`.vscode/tasks.json` 里 `C/C++: gcc.exe build active file` 指向
`D:\Program Files\mingw64\bin\gcc.exe`，**本机不存在**，且它是 `isDefault: true`
——按 Ctrl+Shift+B 会拿宿主 gcc 编译交叉编译工程，纯坑。
已替换为可用的 `Build: cube-cmake (Debug)`（cmake bundle + 往 PATH 注入 ninja）。

### 3. 新增文件
- `.gitignore`：忽略 build/、.codegraph/、.omo/、.tools/、`*.local.json`、`*.bak`；
  并在注释里写清「`.settings/` 和 `.vscode/*.json` 是故意要提交的」。
- `.gitattributes`：`* text=auto`，shell/源码统一 `eol=lf`，二进制标 binary。
  （防止 Windows 检出 CRLF 后 shell 脚本在 WSL/CI 上 `bad interpreter`）
- `githooks/pre-commit`：拦 `C:/Users/<人名>`、`/home/<人名>/`、`/Users/<人名>/`，
  提醒其他盘符绝对路径。已用临时仓库跑通 4 个用例（拦截/放行/真 commit 被拒/修好后可提交）。
  **启用命令：`git config core.hooksPath githooks`**（每个 clone 各做一次）。

### 4. 钩子实现坑（写这类脚本会踩）
- `case` 用的是 **glob** 语法，往里塞 `^(a|b)/` 这种正则**永远不匹配且不报错**。
  白名单/后缀过滤统一用 `grep -qE`。
- 钩子注释里举反例会**拦下钩子自己**，所以 `SKIP_DIR_RE` 必须含 `githooks/`。

### 5. 仍未处理
`.claude/settings.local.json`（及 `.bak`）里大量 Dawn 路径 —— 已纳入 .gitignore，
属机器私有文件，不影响仓库。`.claude/settings.json`（共享）里那条失效的

## 代码评审：AGV_Position_Go()（chassis.c:99）—— 只报告，未改代码

用户明确要求先报问题、不要改。发现 8 项：

1. **编译不过**：`AGV_MovingOffsetStart/End()` 全工程不存在，只有 `Yaw_MovingOffsetStart/End`
   （yawPIDcontroller.c:323/333）。实测 arm-none-eabi-gcc 报 implicit declaration error。
2. **uint16_t 回绕**：`uint16_t dx = x - AGV_Position_X; uint8_t x_flag = (dx>=0)?1:0;`
   → flag 恒为 1，8 个分支里的 `^1` 反向逻辑全是死代码；负差值回绕成 65536-|Δ|，
   会按 ~65 米跑。dy 同理。应改 int16_t。
3. **到位等待被残留数据穿透**：`while(can.rxData[0]!=0xFD || can.rxData[1]!=0x9F);`
   运动完成后 rxData 残留该字节组合，下一次调用立即通过。正确写法项目里已有：
   pick_ctrl.c:75-86（先清 rxFrameFlag 再等 flag&&magic）。
4. **全部等待循环无超时**：chassis/positionPID/yawPID 里都是裸 while，CAN 断链即整机挂死。
   只有 pick_ctrl.c 带了 PICK_MOTOR_DONE_TMO。
5. **AGV_TurnRight 整数下溢**（yawPIDcontroller.c:316）：`(AGV_Direction-1)%4`，
   AGV_Direction 为 uint8_t，为 0 时变成 255；之后 Go 里 4 个 if 全不匹配但
   `AGV_Position_Set(x,y)` 照跑 → 位置悄悄漂移。应 `(x+3)%4`。连续右转 4 次必现。
6. **函数是死代码**：chassis.h 无声明、全工程无调用点、且编译不过。
   task.c 实际用的是手写 Depart/GoBack 序列。
7. **待实车核实**：GoStraight 有 `dir^=1` 而 Translate 没有（dir 语义不一致）；
   Translate 的电机↔WheelN 映射是 1→1,4→2,2→3,3→4 且多两个 `^1`。
8. 小问题：priDir 非法时车不动但坐标仍被 Set；dx/dy 为 0 时仍发 0 脉冲指令。

**修复进展（同日）**：
- #1 用户自己改了（AGV_MovingOffset → Yaw_MovingOffset）。
- #2 已修（chassis.c:101）：差值改用 `int32_t` 承接（不是 int16_t —— uint16_t 两端
  相减最大跨度 ±65535，int16_t 会溢出），dx/dy 保持 uint16_t 存幅值，
  x_flag/y_flag 由 sdx/sdy 符号决定。
- #5 已修（yawPIDcontroller.c:316）：`(AGV_Direction-1)%4` → `(AGV_Direction+3)%4`。
- 修后 `cmake --build build/Debug` 干净通过（RAM 4392B / FLASH 50512B，无警告）。
- #3（残留回执穿透）、#4（无超时）、#7（dir^1 与轮子映射）、#8 仍未处理。
