## 0. 总览

一轮任务 = **两遍取放**。第一遍把原料区的料按任务码送进加工区圆环，第二遍把它们
从圆环取回来、以"同色同环"的规则码放到暂存区高位。

整车由 `TaskProc()` 的状态机推进（[task.c:47](UserCode/Src/task.c#L47)），
每个状态跑完一个阶段就切下一个：

| 状态 | 干什么 | 下一步 |
|---|---|---|
| `Depart` | 收臂到运输位，按 `Route_id` 走路线 1 或 2 离开启动区 | `QRcode` |
| `QRcode` | 扫码 → 显示 → 把任务码下发给相机 | `Move1` |
| `Move1` | 走到原料区 | `Pick1` |
| `Pick1` | **原料区取料** `Pick_RAW()` | `Move2` |
| `Move2` | 走到加工区 | `Place1` |
| `Place1` | **按任务码放进圆环** `Place_ROUGH()` | `Pick2` |
| `Pick2` | **按同样顺序取回** `Pick_ROUGH()` | `Move3` |
| `Move3` | 走到暂存区 | `Place2` |
| `Place2` | **码放到暂存区** `Place_TEMP()`；置 `RerunFlag=1` | `RerunFlag==0` → `Move4`，否则 → `GoBack` |
| `Move4` | 从暂存区回原料区（二周目） | `Pick1` |
| `GoBack` | 按 `Route_id` 回启动区 | `IDLE` |
| `IDLE` | 收臂到 `POS_START` | —（结束） |

`RerunFlag`（[task.c:14](UserCode/Src/task.c#L14)）是"现在是第几轮"的全局标志，
0=第一轮、1=第二轮。它同时决定取哪个颜色数组、以及 `Place_TEMP()` 走 0x04 还是 0x05。

## 1. 启动

### 1.1 初始化顺序（`AGV_Init()`）

```
1. OLED_Init()               显示屏
2. Cam_Init()             相机：发 0x00 探链路，最多等 5s
3. DWT_Init()                微秒级延时
4. AGV_Can_Init()            CAN（四轮 + 机械臂两个步进电机）
5. YawPID_Init()             航向 PID
6. HWT101_Init(&huart5)      陀螺仪（内含 20s 手动校准窗口）
7. Pick_Init()               机械臂：舵机 PWM 起振 + 收到 POS_START
8. Radar_Init()              雷达客户端初始化，不发帧（2026-10-14 新增，见第 7 节）
9. Menu_Init()               阻塞等 A8：C6 选路线 → A8 → C6 选雷达起点方格 → A8
10. Radar_RunOnce()          阻塞跑完雷达任务（约 2~10s），屏幕显示四段结果
11. TaskCode = Depart
```

顺序上有三处是**有意的**：

- `Pick_Init()` 放在 `HWT101_Init()` **之后** —— 陀螺仪那 20s 手动校准期间臂不能动，
  动了会干扰零偏窗口。
- `Menu_Init()` 放在最后 —— 前面全就绪了才开放操作。
- `Radar_Init()` 在 `Menu_Init()` **之前**、`Radar_RunOnce()` 在**之后** ——
  因为起点方格是菜单里选的，而四段规划需要这个值；初始化本身不发帧，提前做没有副作用。

### 1.2 相机初始化失败不拦路 ⚠

`Cam_Init()` 5s 内没收到任何合法回帧，会在 OLED 上写一行 `camera error` 然后
**照常返回**。`cam_start` 这个标志只被**显示**（菜单第二行 `camera OK` / `camera error`），
**没有任何地方拿它拦流程**。

也就是说：相机没接好 / 坏了，菜单上会明明白白写着 `camera error`，但只要你按 A8，
整车照样**完整跑一趟** —— 每个视觉请求白等 10s，`Pick_RAW` 因为拿不到框内颜色
会整段跳过抓取。要不要加门禁见第 6 节。

### 1.3 上电时各执行器的姿态

舵机 PWM 一起振就输出配置的初始角（[servo.c](HARDWARE/Src/servo.c) 配置区）：

| 执行器 | 上电角 | 含义 |
|---|---|---|
| Z 轴旋转（TIM2_CH1/PA5） | 86° | 量程 0~360° 的起始位 |
| 夹爪（TIM3_CH1/PA6） | 110° | **介于 GRAB(129°) 与 RELEASE(75°) 之间，偏夹紧**⚠ |
| 车上转盘（TIM1_CH1/PE9） | 0° | A 槽 |

然后 `Pick_Init()` 调 `Pick_JumpTo POS_START (90, 10, 0)` 把臂收到运输位。

> ⚠ **`Pick_Init()` 不设夹爪角度**。上电夹爪停在 110°（半夹）就往 `POS_START` 摆。
> 第 6 节列了这条。

### 1.4 菜单

`Menu_Init()` 分两阶段（2026-10-14 起，配合雷达模块）：

**阶段1（原有）**：
- `A8` = 进入阶段2（以前是直接启动）
- `C6` = 切换路线（改 `Route_id`，影响 `Depart` / `GoBack` 走哪条路）

**阶段2（新增，仅当 `RADAR_MENU_PICK_ZONE=1`）**：
- `C6` = 雷达启停区 1 ↔ 2（工作区域 zone）
- `A8` = 确认并启动

> 两阶段都是"按下沿"触发、45ms 消抖，A8 在阶段1 只负责翻页，不会误启动；
> 想恢复旧行为（A8 一次启动）把 `menu.c` 顶部的 `RADAR_MENU_PICK_ZONE` 改成 0。
>
> **启停区 ≠ 出发点方格**：启停区是雷达的工作区域（1/2，两区位姿独立保存，
> 命令 `SELECT_ZONE`）；出发点方格是 `PLAN_PATH` 的起点参数（5×5 方格图上的位置）。
> 本项目按"每个启停区一个固定出发点"处理，两个值都在 `radar_config.h` 里，
> 选定启停区时由 `Radar_SetZone()` 一起装好。

## 2. 运行

### 2.1 出发 → 扫码

```
Depart:  Pick_JumpTo POS_RUN          (90, 10, 10)
         AGV_Position_Depart_1() 或 _2()   ← 按 Route_id
QRcode:  QRcode_Task()
```

`QRcode_Task()`（[QRcode.c:99](HARDWARE/Src/QRcode.c#L99)）现在把"扫码"和
"把扫到的任务码告诉相机"**收在了一起**，做的事依次是：

1. `OLED_Clear()`
2. `AGV_QRcode_StartScan()` —— 往 huart3 发 9 字节触发命令
3. `AGV_QRcode_WaitForScan()` —— 最多等 **15s**，逐字节收满 15 字节；
   超时或只收到半截 → **整串换成保底值 `"542+312+452+123"`**，保证后面颜色一定有值可用
4. `QRcode_ParseResult()` —— 按 `xxx,xxx,xxx,xxx` 格式取数：

   | 缓冲区下标 | 变量 | 含义 |
   |---|---|---|
   | 0~2 | `Pick_Color1[0..2]` | 第一轮**取料**颜色（A/B/C 槽顺序）|
   | 4~6 | `Place_Color1[0..2]` | 第一轮**放置**环号（A/B/C 槽顺序）|
   | 8~10 | `Pick_Color2[0..2]` | 第二轮取料颜色 |
   | 12~14 | `Place_Color2[0..2]` | 第二轮放置环号 |

   每个字节都做了 `- '0'`，所以**颜色号就是 1~6 的数值**，不是 ASCII。
5. OLED 分两行显示扫到的串
6. `Cam_RequestTaskCode(Pick_Color1[0..2], 10s)` —— 发 `0x01`，
   **阻塞等相机回 flag=1（任务码已收）**，超时 10s 就往下走

> ⚠ 第二轮任务码 `Pick_Color2` **从没下发给相机**。`case QRcode` 只在第一轮走一次，
> 二周目从 `Move4` 直接回 `Pick1`。相机侧若二周目要用第二轮任务码，得在 `Move4`
> 之前补一条。
>
> ⚠ `RequestTaskCode` 的返回值（1/0）**没判**。超时后照样往下走，相机侧没有任务码
> 的话后面所有颜色都是错的且不会报错。

### 2.2 原料区取料

两版实现，二选一，**当前启用 `Pick_RAW`**（[task.c](UserCode/Src/task.c) 的 `case Pick1`）。

#### 共同的部分

两者开头一样：

```
Pick_JumpTo POS_OBSERVE_RAW     (184, 25, 59)   摆到观察位
Pick_Gripper_Observe()          夹爪 15° 全开（修正期间别挡住相机）
Cam_RequestDisc()  0x02  →  成功才 AGV_Correct(5000)
Pick_Gripper_Release()          夹爪 75°，下去抓之前收位
Pick_JumpTo POS_RUN             收工回运输位
```

**视觉超时就不修正**——超时的话 `dx`/`dy` 还是上一段留下的旧值，拿它驱轮子会把车
带偏；车本来就停在原料区，原地不动直接抓反而更安全。

#### Pick_RAW —— 推算转盘走格（当前启用）

```
发送 0x03，等 flag!=0，拿到 box[0..2]
   box 的下标 0/1/2 == A框/B框/C框 == 相机回报的 左上/下/右上
for i = 0..2:                       i 同时是"任务码第 i 个"和"车上第 i 个槽"
    在 box[] 里找 Pick_Color[i] 在第几格 → j0
    j0 < 0  → 相机没看到这一色，跳过这块，槽位留空
    j = (j0 + grabbed) % 3
    GrabRawBoxToCar(j, i, direct=0)
    grabbed++
```

**为什么是 `(j0 + grabbed) % 3`**：原料转盘每被抓走一块就自动转一格，
剩下的料整体 A→B→C→A 挪一位。`box[]` 只在开头读这一次，读完就"过期"了——
第 i 个颜色要去「它初始所在格 + 已经抓走的块数」上找。**跳过的块不计入**，
因为没拿走就不会转。

> ⚠ 走格方向是"内容索引 +1"，与 A(214°)→B(184°)→C(154°) 的角度递减一致，
> 但没实车验证。反了就把 `(j0 + grabbed) % 3` 改成 `(j0 + 3 - grabbed) % 3`。

#### Pick_RAW_PLUS —— 每块重问（备用，当前未调用）

与 `Pick_RAW` 的区别有两点：

1. **不推算走格**：每抓一块之前都回 `POS_OBSERVE_RAW` 重发一次 `0x03`，
   按相机**当轮**报的颜色直接下手。所以对转盘方向、格数、甚至人工挪过料都不敏感。
   代价是每块多一次"回观察位 + 等相机识别"的往返。
2. **下到料位用 `Pick_MoveTo`**（`direct=1`），不抬到安全高度，贴着观察位高度
   直接转+伸半径，最后才降下去。

"等 flag 再次等于 1"不用额外写：`Cam_RequestBoxColor()` 内部第二段等的就是
`flag!=0`，而且它在发命令**之前**会把完成锁存清掉，等的必然是这条新命令之后
**新来**的那个 flag=1，不是上一条命令的残留。

某一块颜色没报到就跳过该块、槽位留空，但**下一轮照样重新问** ——
这是 PLUS 比 `Pick_RAW` 强的地方：跳过一块不会让后面所有格号全错位。

切换方式：把 `case Pick1` 里的 `Pick_RAW()` 改成 `Pick_RAW_PLUS()`。

#### 抓取动作 `GrabRawBoxToCar(box, slot, direct)`

```
Pick_JumpTo / Pick_MoveTo  →  POS_RAW_A/B/C    下到料位
Pick_TurnTable_Set(slot)                        转盘选槽（此时臂在原料区，不会碰）
Pick_Gripper_Grab()                             夹爪 129° 夹住
Pick_JumpTo POS_CAR                             (4, 31, 28) 摆到车上
Pick_Gripper_Release()                          夹爪 75° 松开
```

- **只有"下到料位"这一步分两版**（`direct` 参数）。从料位回 `POS_CAR` 那一趟
  **一律 `Pick_JumpTo`** —— 那是往车体上方去，路上就是转盘和已放的料，不能贴着扫。
- **先转转盘再摆臂**：三个槽共用 `POS_CAR` 一个臂位姿，靠转盘转角区分。
  转盘转动时必须保证臂不在车体上方。

### 2.3 加工区

#### 放置 `Place_ROUGH()`

```
Pick_JumpTo POS_OBSERVE_CIRCLE (184, 140, 29)   摆到圆环观察位
Pick_Gripper_Observe()                           夹爪 15°
Cam_RequestRing()  0x04  →  成功才 AGV_Correct(5000)
Pick_Gripper_Release()                           夹爪 75°

for i = 0..2:
    PlaceToRing(i, Place_Color[i])
```

`PlaceToRing(slot, ring)`：

```
Pick_TurnTable_Set(slot)     转盘选槽（先转盘）
Pick_JumpTo POS_CAR          再摆臂
Pick_Gripper_Grab()          夹住
MOVE_TO_RING(ring)           → POS_1 / POS_2 / POS_3
Pick_Gripper_Release()       放下
```

| 环号 | 位姿宏 | 坐标 (角度, 高度, 半径) | 位置 |
|---|---|---|---|
| 1 | `POS_1` | (230, 141, 80) | 圆环左 |
| 2 | `POS_2` | (184, 141, 25) | 圆环中 |
| 3 | `POS_3` | (140, 141, 80) | 圆环右 |

**槽位 i 和放置顺序都跟着任务码走**：`Place_Color[i]` 是"第 i 个槽的料该放几号环"，
`i` 从 0 到 2 就是 A→B→C 的顺序，和 `Pick_RAW` 抓取时用的槽序一致。

> `0x04` 返回的**环号被丢弃了**（三个出参传 `NULL`）。环号一律用二维码给的
> `Place_Color[i]`，相机认出的环号和二维码对不上也不会发现。

#### 取回 `Pick_ROUGH()`

```
for i = 0..2:
    GRAB_FROM_RING_AND_PLACE_SLOT(Place_Color[i], i)
Pick_JumpTo POS_RUN
```

`GRAB_FROM_RING_AND_PLACE_SLOT(ring, slot)`：

```
MOVE_TO_RING(ring)           直接去圆环
Pick_Gripper_Grab()          夹住
Pick_TurnTable_Set(slot)     转盘选槽
Pick_JumpTo POS_CAR          摆到车上
Pick_Gripper_Release()       放进槽
```

**用的是和 `Place_ROUGH()` 同一个数组（按 `RerunFlag` 选 `Place_Color1` / `Place_Color2`）**，
这样槽 i 取回来的还是本轮该有的颜色 `Pick_Color[i]`；否则两轮环号不同时槽里的颜色会
被置换，害得后面 `Place_TEMP()` 的同色同环对不上。

这一段**没有视觉交互**。

### 2.4 暂存区 `Place_TEMP()`

环号的取法和前两段不同：**第二轮不按第二轮任务码，而是按第一轮「颜色→环位」的
对应关系，同色同环码垛**（`Place_RingSameAsLastRound()`）。
布尔量 `is_high = (RerunFlag == 1)` 决定放置时用普通位还是高位。

视觉修正分两种：

| 轮次 | 观察位 | 命令 | 干什么 |
|---|---|---|---|
| 第一轮 | `POS_OBSERVE_CIRCLE (184,140,29)` | `0x04` | 和 `Place_ROUGH` 同一处，请求圆环 |
| 第二轮 | `POS_OBSERVE_TEMP (184,80,29)` | `0x05 color` | 对正"第一轮放在 2 号环上的那一块"的颜色 |

第二轮 `color_to_send` 的求法：第一轮哪一槽放进了 2 号环 → 取那一槽的颜色
（`Place_Color1[k]==2` → `color_to_send = Pick_Color1[k]`）。
**颜色号是 1~6，所以 0 只可能是"第一轮没有哪一槽进 2 号环"**，
这时没有颜色可问，发 `AA 05 00 BB` 相机也不认，直接当失败处理、不做修正。

两轮都收进 `vision_ok`，最后 `if(vision_ok) AGV_Correct(5000)`，然后：

```
Pick_Gripper_Release()
GRAB_AND_PLACE_TO_RING_SLOT_EX(0, Place_Color[0], is_high)   A 槽
GRAB_AND_PLACE_TO_RING_SLOT_EX(1, Place_Color[1], is_high)   B 槽
GRAB_AND_PLACE_TO_RING_SLOT_EX(2, Place_Color[2], is_high)   C 槽
Pick_JumpTo POS_RUN
```

高位对应的位姿是 `POS_1_HIGE (230,81,80)` / `POS_2_HIGE (184,81,25)` /
`POS_3_HIGE (140,81,80)`。

### 2.5 返回

`GoBack` → `AGV_Position_GoBack_1()` 或 `_2()`（按 `Route_id`）→ `IDLE` →
`Pick_JumpTo POS_START`，整车回到初始姿态。

## 3. 视觉接口约定

### 3.1 帧格式与命令表

定长帧：`AA <cmd> <payload...> BB`

**电控 → 相机**

| 命令 | 帧 | 含义 |
|---|---|---|
| `0x00` | `AA 00 BB` | 空闲（探链路用，**发了不等**）|
| `0x01` | `AA 01 c1 c2 c3 BB` | 下发任务码 |
| `0x02` | `AA 02 BB` | 请求圆盘中心位置偏差 |
| `0x03` | `AA 03 BB` | 请求三个框内颜色 |
| `0x04` | `AA 04 BB` | 请求圆环 |
| `0x05` | `AA 05 color BB` | 请求指定颜色 |

**相机 → 电控**（任何模式下都循环回发）

| 命令 | 帧 | flag 含义 |
|---|---|---|
| `0x00` | `AA 00 flag BB` | 随意 |
| `0x01` | `AA 01 flag BB` | flag=1 任务码已收 |
| `0x02` | `AA 02 flag dxH dxL dyH dyL BB` | flag=1 圆盘中心已识别 |
| `0x03` | `AA 03 flag c1 c2 c3 BB` | flag=1 框内从无到有；c1/c2/c3 = **左上/下/右上** |
| `0x04` | `AA 04 flag dxH dxL dyH dyL BB` | flag = 圆环编号 1/2/3，0=未识别 |
| `0x05` | `AA 05 flag dxH dxL dyH dyL BB` | flag=1 识别到对应颜色 |

`dx`/`dy` 是有符号 `int16`、高字节在前。

**`0x03` 回报顺序与原料区三个位姿的对应**（已对齐，不要改错）：

| 相机 | 位姿宏 | 坐标 |
|---|---|---|
| c1 = 左上 | `POS_RAW_A` | (214, 62, 79) |
| c2 = 下 | `POS_RAW_B` | (184, 62, 29) |
| c3 = 右上 | `POS_RAW_C` | (154, 62, 79) |

### 3.2 两段式等待

五个请求式 API（`Cam_RequestTaskCode` / `RequestDisc` / `RequestBoxColor` /
`RequestRing` / `RequestColor`）**走同一条路** `Cam_WaitSettle()`：

```
清掉两个锁存（s_ackCmd / s_doneCmd）
发出命令
── 第一段：等「相机回了一帧，且它的第二字节 == 刚发出去的命令码」
     每 100ms 没动静就补发一次，10s 超时 → 返回 0
── 第二段：等这同一条命令回 flag != 0（相机把活干完了）
     超时 settle_ms → 返回 0，**这一段不补发**
返回 1
```

**为什么第一段必须按命令码匹配**：相机在任何模式下都会持续往回发数据，
所以"收到一帧"完全不能说明它收到了我们的命令，必须按第二字节比对。
这也是唯一的链路级握手判据。

返回值统一：**1 = 两段都过，出参有效；0 = 任一段超时，出参没有意义**。
调用方必须判返回值，别拿旧值往下走。

### 3.3 位置修正 `AGV_Correct(timeout_ms)`

内部闭环，读全局 `dx`/`dy`/`cam_flag`：

- 每 `AGV_CTRL_TICK_MS = 40ms` 一拍（≈20Hz）
- `cam_flag == 0` 时**不下发**（保持上次轮速），并清零对准计数
- `|dx|,|dy|` 都 ≤ `AGV_ALIGN_WIN_PX = 1` 像素，连续 `AGV_ALIGN_HOLD_CNT = 4` 拍
  （≈200ms）才认定对准、退出
- 退出时立即停车，并回到修正前的航向

调用点一律是"**视觉请求成功了才修正**"，超时就跳过，见 2.2 的说明。

> ⚠ `AGV_Correct()` 只看 `cam_flag` 不看 `cam_mode`。`cam_flag` 任何命令帧都会刷新，
> 而 `dx`/`dy` 只有 `0x02`/`0x04`/`0x05` 会写。正常时序下相机停在 `0x02` 模式碰不上；
> 要收紧就得给它加"期望命令码"。

## 4. 机械臂与执行器约定

### 4.1 位姿宏（[pick.h](HARDWARE/Inc/pick.h)）

宏是**括号宏**，用不带括号的方式调用：`Pick_JumpTo POS_CAR;` 展开成
`Pick_JumpTo(4.0f, 31.0f, 28.0f)`。

| 宏 | (Z 角度, 高度 mm, 半径 mm) | 用途 |
|---|---|---|
| `POS_DEFAULT` | (90, 0, 25) | 复位 |
| `POS_START` | (90, 10, 0) | 上电 / 结束收缩位 |
| `POS_RUN` | (90, 10, 10) | 车移动时的姿态 |
| `POS_OBSERVE_RAW` | (184, 25, 59) | 观察原料 |
| `POS_OBSERVE_CIRCLE` | (184, 140, 29) | 观察圆环 |
| `POS_OBSERVE_TEMP` | (184, 80, 29) | 观察暂存区 |
| `POS_RAW_A/B/C` | (214/184/154, 62, 79/29/79) | 原料三个抓取位 |
| `POS_CAR` | (4, 31, 28) | 车上唯一臂位姿 |
| `POS_1/2/3` | (230/184/140, 141, 80/25/80) | 圆环 1/2/3 号 |
| `POS_1/2/3_HIGE` | (230/184/140, 81, 80/25/80) | 圆环高位 |

`PICK_SAFE_HEIGHT_MM = 7.0f`：门字形轨迹抬到的"安全高度"，越小的 mm 越高越安全。

### 4.2 车上转盘槽位

车上是「**同一个臂位姿 `POS_CAR` + 转盘舵机转角**」，不是三个臂位姿：

| slot | 舵机角 | 槽 |
|---|---|---|
| 0 | 0° | A |
| 1 | 120° | B |
| 2 | 240° | C |

`Pick_TurnTable_Set(slot)` 选槽，内部 `Servo_SetAngleSmooth` + `SERVO_T_SETTLE_MS`
停稳裕量。**时序约定：先转盘、后摆臂**（转盘转动时臂不在车体上方）。

`slot` 的下标约定和 `Pick_Color[]` / `Place_Color[]` 完全一致，
`Pick_RAW` 抓第 i 个颜色就放第 i 个槽。

### 4.3 夹爪三段角度

| 动作 | 角度 | 什么时候 |
|---|---|---|
| `Observe` | 15° | **观察 / 视觉修正期间** —— 全开，别挡住相机 |
| `Release` | 75° | **下去抓之前**、放下之后 |
| `Grab` | 129° | 夹住物料 |

统一规律：**修正期间 `Observe`，动作前 `Release`，夹住那一刻 `Grab`。**

### 4.4 两个动作函数的区别

| 函数 | 轨迹 | 代价 | 什么时候用 |
|---|---|---|---|
| `Pick_JumpTo` | 门字形：先升到 `PICK_SAFE_HEIGHT_MM` 再转+伸半径，最后降高度 | 慢，多一次升降 | 路上可能有料台/已放物料 —— **默认用这个** |
| `Pick_MoveTo` | 直接到位：贴当前高度直接转+伸，最后才改高度 | 快 | 起终点之间确实空 |

两者都不控制夹爪，由调用方按需开合。半径和转角都已到位时两者都会短路成"只改高度"。

## 6. 未定项 / 待实车验证

按影响排序：

1. **相机挂了没人拦** —— `Cam_Init()` 超时只写一行 `camera error` 就往下走，
   全工程不检查 `cam_start`。要不要加门禁？
2. **任务码下发超时后没人管** —— `QRcode_Task()` 里 `RequestTaskCode` 的返回值没判。
   超时该报错停 / 重试一次 / 硬着头皮走，还没定。
3. **第二轮 `Pick_Color2` 从没下发** —— 相机侧二周目若要用第二轮任务码，
   得在 `Move4` 之前补一条。
4. **转盘走格方向未验证** —— `(j0 + grabbed) % 3` 是"内容索引 +1"，反了要改成
   `(j0 + 3 - grabbed) % 3`。先空跑一轮，盯住第二块是不是抓在该在的格上。
5. **`Pick_Init()` 不设夹爪角度** —— 上电夹爪停在 110°（半夹）就往 `POS_START` 摆。
6. **转盘舵机（`SERVO_TURN`, TIM1_CH1/PE9）** —— 接线、0/120/240 的角度与方向、
   `SERVO_T_SETTLE_MS = 300` 都是估的。**TIM1 预分频必须是 167**（不是 TIM2/3/4 的 83），
   按 83 配会得到 100Hz PWM，舵机抖动或不动作。
7. **`POS_CAR` 仍是原 `POS_A` 的 (4, 31, 28)** —— 转盘方案下这是车上唯一的臂位姿，必须实测。
8. **`PICK_SAFE_HEIGHT_MM = 7.0f`** —— 推的。首次试跑把料换成高一点的，或空跑观察抬升时机。
9. **`Pick_RAW_PLUS` 下料位用 `Pick_MoveTo`** —— 观察位 25mm 贴着扫到料位，
   路上会不会蹭到料台要观察。**当前未启用**，切换是 `case Pick1` 一行的事。
10. **`AGV_Position_Depart_2()` 没锚定坐标** —— 路线 2 的跟踪坐标一直停在 (0,0)，
    实际移动了约 1010mm，之后每次 `AGV_Position_Go()` 算的距离都是错的。
11. **`AGV_Correct()` 只看 `cam_flag` 不看 `cam_mode`** —— 见 3.3 的说明。
12. **`0x04` 返回的环号被丢弃** —— `Place_ROUGH()` 里三个出参传 `NULL`。

## 7. 雷达（启动时的四段路径规划）

2026-10-14 新增。启动时用雷达扫一遍场地方格，规划四段路径；`Radar_RunOnce()` 返回后
**整车流程不再使用雷达**（`Radar_Service()` 不必再调用）。协议与客户端来自雷达厂商例程
（`Radar/Src/radar_client.c`，未改动），板级适配与流程胶水是本工程新写的。

### 7.1 四段路线与两个"区"

路线是"一串端点"：`{出发点, 14, 10, 22, 14}` → 四段 `出发点→14`、`14→10`、`10→22`、`22→14`。

| 概念 | 是什么 | 谁给 | 在哪配 |
|---|---|---|---|
| **启停区**（工作区域 zone 1/2） | 雷达的两个发车区，**两区位姿独立保存**，用 `SELECT_ZONE(0x05)` 切换 | 启动菜单阶段2 里 C6 选 | `radar_config.h` 的 `RADAR_ZONE_DEFAULT` |
| **出发点方格**（0~24） | `PLAN_PATH(0x14)` 的起点参数，5×5 方格图上车所在的位置；雷达不会自己知道车停在哪 | 跟着启停区走（每区一个固定值） | `radar_config.h` 的 `RADAR_ZONE1/2_START_GRID` |
| 雷达位姿（X/Y/朝向） | 雷达自身的安装位置与朝向；两区的窗口不同（区域1 的 Y 1900~2600、区域2 的 Y −200~500） | 跟着启停区走 | `radar_config.h` 的 `RADAR_ZONE1/2_POSE_*` |

`Radar_SetZone(zone)` 一次做完三件事：登记选区请求 → 按该区设位姿 → 按该区设出发点方格。

结果通过 `Radar_GetLeg(i, &path)` 取，每段含 `status`、`start`、`goal`、`waypoints[]`
（节点序列，**不含起点、含终点**，元素是雷达方格编号 0~24）。屏幕结束时显示四行
`Lx 起点>终点 s状态 n节点数`。

### 7.2 执行时序（由 radar_client 的非阻塞状态机推进）

```
Radar_Init()      → RadarClient_Init() + RequestSelectZone(区域) + Launch_Init()   （不发帧）
Radar_RunOnce()   → 循环 Radar_Service()（= RadarClient_Poll + Launch_Poll）直到结束：
     1. 等 READY：HELLO 握手 + 区域确认 + 读雷达保存状态
     2. 设位姿（默认 CMD_SET_POSE 0x06，只改本次上电的会话位姿）
     3. 方格扫描 CMD_SINGLE_MEASURE 0x08（14 圈）
     4. 回读保存状态确认 grid_result_valid=1
     5. 依次四段 CMD_PLAN_PATH 0x14
     6. 定向 STOP 收尾
```

### 7.3 四条不能踩的线

1. **必须用"方格扫描"(0x08)，不能用"单次完整障碍扫描"(0x07)**：只有方格扫描会把结果
   写进雷达 Flash，而路径规划只认 Flash 里那份。
2. **只在 `Radar_Init()` 里选区一次**：`SELECT_ZONE` 会重新载入该区 Flash 位姿、覆盖刚设的
   会话位姿。断链重连时客户端会自动重新选区，同样会覆盖 —— 要长期保留就把
   `LAUNCH_SAVE_POSE_TO_FLASH` 改 1。
3. **位姿越界一帧都不发**：两区 X 都必须 −200~500；区域1 的 Y 1900~2600，区域2 的 Y −200~500。
   越界时请求直接返回 `BAD_PARAMETER`，现象是"雷达任务刚开始就结束"（屏幕上 `f2`）。
4. **方格 ≠ 车的坐标**：方格是雷达的 0~24 编号，目前只取规划结果、**没有**转成
   `AGV_Position_Go(x,y)` 的动作（映射表还没定）。

### 7.4 串口与中断

| 项 | 值 |
|---|---|
| 串口 | `UART4` / `PC10(TX)` / `PC11(RX)` / 115200 8N1（改动记录第 26 节预留的口） |
| RX | `DMA1_Stream2 / CHANNEL_4`，循环模式，关半满中断（`.ioc` 里没有，由 `radar_uart_port.c` 首次调用时自建） |
| TX | `HAL_UART_Transmit_IT` 中断发送（一帧最大 237B，115200 下约 21ms） |
| 中断入口 | `UART4_IRQHandler` / `DMA1_Stream2_IRQHandler`，定义在 `radar_uart_port.c`（照 `hwt101.c` 自持 `UART5_IRQHandler` 的做法） |
| NVIC | 优先级 6，低于 TIM7/CAN/USART1(0)，与 UART5 同级 |
